# Auth Architecture Refactor Plan

## Problem Analysis

**Current Issues:**
1. **Double layout**: Root `+layout.svelte` has Sidebar/Navbar AND `(app)/+layout.svelte` also has Sidebar/Navbar
2. **Login page showing app layout**: Root layout has conditional `if isAuthenticated` that renders Login component but auth logic is flawed
3. **Root layout contains auth logic**: All auth logic (isAuthenticated, protectRoute, etc.) is in root layout
4. **Duplicate protection**: Both root layout hooks AND hooks.client.ts have auth protection

## Root Cause

The root `+layout.svelte` (lines 1-66) contains:
- Sidebar component (line 6)
- Navbar component (line 7)  
- Login component (line 8)
- Auth logic with onMount and protectRoute (lines 12-21)
- Conditional rendering `{#if $isAuthenticated}` (lines 26-38)

When `(app)/+layout.svelte` is rendered, it ALSO contains Sidebar+Navbar, causing duplication.

## Architecture Fix

### 1. Root Layout (`/src/routes/+layout.svelte`)

```svelte
<script>
  import '../lib/app.css';
  let { children } = $props();
</script>

{@render children()}
```

**Reason**: Root layout should ONLY render child routes. No auth logic, no sidebar, no navbar.

### 2. App Layout (`/src/routes/(app)/+layout.svelte`)

<script>

  import Navbar from '$lib/components/Navbar.svelte';

**Reason**: Clean layout for login - no sidebar, no navbar.

### 5. Update `hooks.client.ts`

```typescript
import { checkAuth } from '$lib/api/auth';
import { get } from 'svelte/store';
import { auth } from '$lib/stores/auth';

const ROLE_PERMISSIONS: Record<string, string[]> = {
	admin: ['/dashboard', '/inventory', '/reports', '/pos'],
	cashier: ['/pos']
};

export async function handle({ event, resolve }) {
	const path = event.url.pathname;
	
	// Allow static assets and login
	if (path.startsWith('/_app') || path.startsWith('/login')) {
		return resolve(event);
	}
	
	// Check auth
	const isAuth = await checkAuth();
	const state = get(auth);
	
	if (!isAuth || !state.user) {
		return Response.redirect('/login', 303);
	}
	
	// Role-based route protection
	const allowedRoutes = ROLE_PERMISSIONS[state.user.role] || ['/pos'];
	const hasAccess = allowedRoutes.some(route => path.startsWith(route));
	
	if (!hasAccess) {
		return Response.redirect(allowedRoutes[0] || '/pos', 303);
	}
	
	return resolve(event);
}
```

## Why This Architecture is Correct

1. **Single responsibility**: Each layout has one job
2. **No duplication**: Sidebar+Navbar exists in exactly one place
3. **Clean separation**: Auth routes vs protected app routes
4. **Proper protection**: Route guard at framework level, not UI level
5. **Scalable**: Adding new protected routes just means adding under `(app)/`
