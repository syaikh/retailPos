# Plan: Retail POS Rebuild - Clean Architecture with Svelte 5 + Go 1.26 + PostgreSQL 18 + WebSocket

## Objective
Rebuild retail-pos system menggunakan clean architecture dengan spesifikasi:
- Frontend: Svelte 5 + Tailwind CSS 4 (latest stable)
- Backend: Go 1.26 + PostgreSQL 18
- WebSocket: Real-time sync antar kasir
- Environment: LAN lokal (multi-kasir) → skalabel ke multi-store
- Admin access: Frontend-privilege only, no direct DB access

## Architecture Decisions (ADRs)

### 1. Branch Strategy: New Project (Clean Slate)
**KEPUTUSAN**: Buat repository baru dari awal, JANGAN branch dari codebase lama.

**ALASAN**:
- Codebase lama sudah terikat SvelteKit (framework bawaan backend) → melanggar constraint "Go only" untuk backend
- Arsitektur lama menumpang dua backend (Go + Vite dev server) → overkill untuk LAN
- Clean architecture memerlukan pemisahan ketat yang lebih mudah dibangun dari nol
- Database perlu redesign (normalisasi ulang) untuk audit trail & multi-store support
- Dependency management lebih rapi (Go 1.26 + Svelte 5 fresh install)

**IMPLIKASI**: 
- Copy fitur-fitur bisnis dari codebase lama sebagai referensi
- Migrasi logika domain (bukan kode) ke arsitektur baru

### 2. CORS Policy: Development vs Production
**KEPUTUSAN**: CORS **diperlukan** di development, **opsional** di production LAN.

**ALASAN**:
- **Dev Environment** (Vite HMR di port 5173, Go di 8080): Perlu CORS karena beda origin
- **Production LAN** (satu domain, embedded static): Tidak perlu CORS jika Go serve static files
- Jika tetap terpisah (proxy/Nginx): CORS tetap dibutuhkan

**IMPLEMENTASI**:
```go
// Dev: Izinkan localhost:5173
// Prod: Izinkan domain spesifik atau same-origin via embedded static
r.Use(cors.New(cors.Config{
    AllowOrigins:     []string{os.Getenv("FRONTEND_URL")},
    AllowCredentials: true,
}))
```

### 3. Container Strategy: Podman PostgreSQL + Native Go
**KEPUTUSAN**: PostgreSQL di Podman, Go binary native (tanpa container).

**ALASAN**:
- PostgreSQL di container: Isolasi service, mudah backup/restore
- Go native: Performa maksimal, deployment sederhana (satu binary), cocok untuk LAN
- Tidak perlu orkestrasi kompleks (Docker Compose) untuk skala LAN

**DEPLOYMENT FLOW**:
1. `podman run -d postgres:18` (LAN network)
2. Build Go: `go build -o retailpos`
3. Jalankan: `./retailpos` (connect ke podman postgres)

## Security Principle
> **Admin ≠ Database Access**. Admin adalah *frontend privilege role*, bukan *database superuser*. Semua akses data melalui API endpoint dengan RBAC enforcement. App menggunakan database user dengan privilege minimal (SELECT/INSERT/UPDATE/DELETE saja).

## Planned Changes

### 1. **Backend: Restrict Admin-Only Endpoints**
**Location**: `internal/handler/*.go`

**Current State**: Admin endpoints like `/api/admin/users`, `/api/admin/roles` exist. These are **API endpoints**, not database access — but they expose bulk data.

**Action**:
- Keep endpoint logic, but enforce **strict RBAC**
- Add middleware: `requirePermission("admin:read")` or `requireRole("admin")`
- **Do NOT** create separate database connection for admin
- Audit: Ensure no handler uses direct SQL without repo layer

**Files to Review**:
- `internal/handler/handlers.go` (ListUsers, ListRoles, CreateRole, etc.)
- `internal/auth/middleware.go` (ensure middleware enforces permissions)

**Validation Rule**:
```go
// ✅ GOOD: Uses existing repo, checks permission
if !h.hasPermission(c, "user:read") { c.Abort(); return }

// ❌ BAD: Direct DB access bypassing repo
// db.Query("SELECT * FROM users") 
```

---

### 2. **Frontend: Hide Admin UI from Non-Admins**
**Location**: `web/src/routes/(app)/admin/+page.svelte`, `web/src/routes/+layout.svelte`

**Current State**: Need to verify if admin routes are protected client-side.

**Action**:
- Add route guard: redirect non-admin users from `/admin/*`
- Hide admin navigation items based on role (from auth store)
- Fetch user role on app init (already exists via `/api/auth/validate`)

**Example** (`+layout.svelte`):
```svelte
<script>
  import { onMount } from 'svelte';
  import { goto } from '$app/navigation';
  import { auth } from '$lib/stores/auth';

  onMount(async () => {
    if (!$auth.user || $auth.user.role !== 'admin') {
      goto('/');
    }
  });
</script>
```

**Admin Nav Visibility**:
```svelte
{#if $auth.user?.role === 'admin'}
  <a href="/admin/users">Manage Users</a>
{/if}
```

### 3. **Permission System: Enforce at API Gateway Level**
**Location**: `internal/auth/middleware.go`, `internal/handler/handlers.go`

**Current State**: `hasPermission` helper exists in handlers.

**Action**:
- Move permission checks to **Gin middleware** (reusable)
- Protect routes by permission code, not just role
- Example permissions: `user:read`, `user:write`, `product:delete`, `report:generate`

**Middleware**:
```go
func RequirePermission(perm string) gin.HandlerFunc {
  return func(c *gin.Context) {
    perms, _ := c.Get("permissions")
    if !hasPermission(perms, perm) {
      c.AbortWithStatusJSON(403, gin.H{"error": "forbidden"})
      return
    }
    c.Next()
  }
}
```

**Route Usage**:
```go
admin := r.Group("/admin")
admin.Use(auth.RequireRole("admin"))
{
  admin.GET("/users", RequirePermission("user:read"), h.ListUsers)
}
```

### 4. **Database: No Admin Bypass Path**
**Location**: All `internal/repo/*.go` files

**Review**:
- Ensure **no repository function** checks `is_admin` flag to bypass row-level security
- All queries must include `store_id` filter (multi-tenant safety)
- Admin users are just users with `role='admin'` — they use same DB connection pool

**Example** (`product_repo.go`):
```go
// ✅ Both admin and cashier use same function
func (r *ProductRepo) GetAll(limit, offset int, search string, storeID *int) ([]Product, int, error) {
  query := "SELECT * FROM products WHERE store_id = $1"
  // Admin doesn't get special "bypass store_id" clause
  // Instead, admin users have access to all stores via store_id list
}
```

**Fix if needed**: If admin should see all stores, handle via **multiple store IDs** in JWT, not by skipping filters.

### 5. **Audit: Remove Dangerous Endpoints (if any)**
Search for patterns that expose raw DB access:
- Custom SQL via HTTP params (e.g., `?query=SELECT...`) — **remove immediately**
- Generic "export all tables" endpoints
- Debug endpoints returning full row data

**Search**:
```bash
grep -r "SELECT\|INSERT\|UPDATE\|DELETE" internal/handler/ | grep -v "repo"
grep -r "db.Exec\|db.Query" internal/handler/  # Should be minimal
```

### 6. **Frontend API Client: Centralize with Interceptors**
**Location**: `web/src/lib/api/client.ts`

**Current State**: Uses Axios with interceptors for auth.

**Enhancement**:
- Add interceptor to attach permission metadata to requests
- Handle 403 globally (redirect to /unauthorized)

```typescript
client.interceptors.response.use(
  res => res,
  error => {
    if (error.response?.status === 403) {
      // Frontend privilege check failed
      alert('Access denied: insufficient privileges');
      goto('/');
    }
    return Promise.reject(error);
  }
);
```

### 7. **WebSocket: Secure Real-Time Events**
**Location**: `internal/ws/hub.go`, `web/src/lib/stores/ws.ts`

**Current State**: Broadcasts events to all connected clients.

**Action**:
- **Do not expose sensitive data** via WS (e.g., full user list, passwords)
- Filter events by `store_id` (already partially done)
- Admin-only events (e.g., `user_deleted`) should only go to admin sessions

**Check**:
```go
// In hub.go, before broadcasting:
if event.RequiresAdmin && !client.isAdmin {
  continue
}
```

## Summary of Principles

| Layer | Rule |
|-------|------|
| **Database** | No admin superuser. App uses single least-privilege DB user. |
| **Backend** | All data access via repo layer. RBAC enforced on every handler. |
| **Frontend** | Admin UI hidden from non-admins. Guards on routes. |
| **API** | No special "/admin/database/*" endpoints. All access through standard resource endpoints with permissions. |
| **WebSocket** | No raw table dumps. Events scoped by store/role. |

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Admin expects to see all stores data | Add `store_ids` to JWT, allow multiple in queries |
| Legacy code has `if isAdmin { skip filter }` | Search & remove all such patterns |
| Frontend route guard is only UI, API still exposed | Backend **must** enforce — frontend is convenience only |
