# Plan: Build Actual Pages for Retail POS System

## Current State
- Frontend is a single `index.html` prototype with placeholder `alert()` for card clicks
- Svelte page components exist in `web/lib/pages/` but are not integrated
- E2E tests expect real navigation to `/pos`, `/inventory`, `/admin` pages
- Build output (`dist/`) contains only the static prototype HTML

## Goal
Replace placeholder alerts with actual SPA navigation using Svelte components, enabling:
- Real POS page with product grid, cart, checkout
- Real Inventory page with product management
- Real Admin panel with user/role management
- All E2E tests to pass (currently ~21 passing, many skipped)

---

## Phase 1: Set Up Svelte SPA Foundation

**Duration:** 1-2 days  
**Risk:** Low (mostly mechanical setup)

### 1.1 Choose Routing Strategy
- Option A: **SvelteKit** (full framework, file-based routing) - requires migration
- Option B: **Custom hash router** (lightweight, already have `lib/router.ts`)
- **Recommendation:** Option B to keep it simple and aligned with existing code

### 1.2 Create Main App Component
- Create `web/lib/App.svelte` as root component
- Implement hash-based router: `#/`, `#/pos`, `#/inventory`, `#/admin`, `#/login`
- Add layout with:
  - Navbar (logo, user menu, logout)
  - Sidebar (navigation)
  - Main content area (`<slot>` or dynamic component)

### 1.3 Update index.html
- Replace static HTML with `<div id="app"></div>`
- Add script tag to compile and mount Svelte app
- Ensure Vite build outputs proper bundles

### 1.4 Implement Route Guards
- Protected routes: `/pos`, `/inventory`, `/admin` require auth
- Redirect to `/login` if not authenticated
- Store auth state in localStorage/sessionStorage

## Testing Strategy Per Phase

After each phase:
1. Run relevant E2E test file: `npx playwright test tests/e2e/pos-flow.spec.ts`
2. Fix any failing tests immediately
3. Verify manual testing (`./deploy/podman-deploy.sh restart`)
4. Commit changes with descriptive message

**Final gate:** All 100+ E2E tests must pass before marking "complete".

## Alternative: Incremental Migration

If full SPA migration is too big a change, consider:
1. Keep `index.html` as multi-page app
2. Each card click loads separate HTML page (POS, Inventory, Admin)
3. Each page is standalone Svelte app (multiple entry points)
4. Easier to build incrementally, but loses SPA benefits

**Recommendation:** Go with SPA approach for better UX and maintainability.
