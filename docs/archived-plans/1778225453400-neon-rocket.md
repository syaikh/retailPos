# Plan: Modifikasi Fitur Pencarian Produk - Tambah Barcode

## Tujuan
Memodifikasi fitur pencarian produk pada halaman POS agar dapat mencari produk berdasarkan **nama, SKU, atau barcode**. (SKU sudah tersedia, menambahkan barcode).

## Analisis Saat Ini

### Backend
- File: `internal/repository/postgres_repository.go`
- Fungsi: `GetAllProducts` (baris 399-498)
- Query saat ini:
  ```sql
  AND (p.name ILIKE $1 OR p.sku ILIKE $1)
  ```
- **Tidak termasuk barcode** pada kondisi pencarian.

### Frontend
- **PosPage.svelte** (`web/src/lib/pages/PosPage.svelte:159`): Placeholder "Search products..."
- **InventoryPage.svelte** (`web/src/lib/pages/InventoryPage.svelte:266`): Placeholder "Search products..."
- Keduanya memanggil endpoint `/api/products?search=<query>`.

### Test
- **pos-flow.spec.ts** (baris 198): Test expecting placeholder `"Search products (name or SKU)..."` (mismatch dengan aktual "Search products...").

## Rencana Modifikasi

### 1. Backend - Tambah Barcode pada Search Query

**File**: `internal/repository/postgres_repository.go`

**Perubahan** (dua lokasi dalam fungsi `GetAllProducts`):
- Baris 408: Ubah dari  
  `query += " AND (p.name ILIKE $1 OR p.sku ILIKE $1)"`  
  menjadi  
  `query += " AND (p.name ILIKE $1 OR p.sku ILIKE $1 OR p.barcode ILIKE $1)"`
- Baris 435: Sama perubahan di query selection.

**Detail**:
- Cari blok `if search != ""` untuk COUNT query (line 407-410) dan SELECT query (line 434-437).
- Tambah `OR p.barcode ILIKE $1` di kedua blok.
- Kolom `barcode` tipe `VARCHAR` bisa NULL; `ILIKE` akan skip NULL values (tidak match) — sesuai expected behavior.
- Parameter `$1` tetap digunakan, aman dari SQL injection.

### 2. Frontend - Update Placeholder Text

**File**: `web/src/lib/pages/PosPage.svelte`
- Baris 159: Ubah placeholder dari `"Search products..."` menjadi `"Search products (name, SKU, or barcode)..."`

**File**: `web/src/lib/pages/InventoryPage.svelte`
- Baris 266: Ubah placeholder dari `"Search products..."` menjadi `"Search products (name, SKU, or barcode)..."`

### 3. Update E2E Test

**File**: `tests/e2e/pos-flow.spec.ts`
- Baris 198: Ubah selector placeholder dari `"Search products (name or SKU)..."` menjadi `"Search products (name, SKU, or barcode)..."`

## Dampak Sistem

### Functional
- ✅ Pencarian produk kini mencakup barcode selain nama dan SKU.
- ✅ Query `search` parameter akan match dengan field `barcode` (case-insensitive).
- ✅ Backward compatible: existing search by name dan SKU tetap bekerja.

### Non-Functional
- **Query Performance**: Tambah kondisi `OR p.barcode ILIKE $1` dapat sedikit menambah overhead, namun data produk biasanya tidak exceed ribuan baris. Index pada barcode belum ada; bila dataBesarr, pertimbangkan index partial/full-text (out of scope).
- **UX**: Tidak ada perubahan UI; fungsionalitas searchable field perlu dikomunikasikan ke user secara manual atau via placeholder (opsional, di luar scope minimal).

## Testing Strategy

1. **Manual Testing**:
   - Cari produk menggunakan nama (existing behavior)
   - Cari produk menggunakan SKU numerik (existing behavior)
   - Cari produk menggunakan barcode (new behavior)
   - Test dengan barcode yang NULL (harus tidak muncul)

2. **Automated Testing**:
   - Update placeholder di e2e test agar pass
   - Pertimbangkan menambah test case untuk search by barcode

## Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| Barcode NULL values tidak pernah match | Expected behavior | Documentasi: barcode harus memiliki value untuk bisa dicari |
| Performansi query lambat | Medium | Untuk data besar, pertimbangkan full-text search (out of scope) |
| Placeholder terlalu panjang | Low | Tetap readable, gunakan ellipsis jika perlu |

## Rollback Plan

- Kembalikan query di `postgres_repository.go` ke versi sebelumnya
- Kembalikan placeholder text ke versi sebelumnya
- Tidak ada data migration yang berubah
