# Plan: Split InventoryPage into ProductsPage and StockPage

## Goal
Split the current InventoryPage (1572 lines, mixing product master data + stock management) into two dedicated pages:
- **ProductsPage** (`/inventory/products`) — Product master data CRUD
- **StockPage** (`/inventory/stock`) — Stock levels, adjustments, movements, low-stock alerts

## Current State Analysis

**InventoryPage.svelte** (~1572 lines) contains:
- Product table with sorting, searching, category filtering, pagination
- Add/Edit product modal (name, SKU, barcode, category, brand, price, cost, stock, unit of measure, tax class, weight, description, status)
- Delete product modal
- Stock adjustment modal (quantity change + notes)
- Product detail drawer (stock & logistics block, financial block, description, audit trail)
- Low-stock toggle filter
- Category filter modal
- Permissions: `canManageInventory` (superadmin, admin, manager, staff), `canEdit` (superadmin, admin, manager), `canAdjustStock` (superadmin, admin, manager, staff), `canDelete` (superadmin, admin)

**Routing** (`App.svelte`):
- Single route: `/inventory` → InventoryPage
- Sidebar: single "Inventory" item at `/inventory`

**Tests**: `InventoryPage.svelte.test.ts` (~924 lines) — comprehensive unit tests for all inventory features

**E2E tests**: `tests/e2e/inventory.spec.ts` — 13 tests covering UI and API

## Architecture

### Routes
| Route | Component | Purpose |
|-------|-----------|---------|
| `/inventory` | Redirect → `/inventory/products` | Backward compatibility |
| `/inventory/products` | ProductsPage | Product master data CRUD |
| `/inventory/stock` | StockPage | Stock management & adjustments |

### Sidebar Changes (`Sidebar.svelte`)
Replace single "Inventory" item with parent "Inventory" group containing:
- "Products" → `/inventory/products` (Package icon)
- "Stock" → `/inventory/stock` (BarScale or ClipboardList icon)

For collapsed sidebar: show "Inventory" label with sub-items expanding on hover/click.

### Shared Components to Extract
1. **ProductFormModal** — Add/edit product form (currently inline in InventoryPage ~100 lines of form HTML)
2. **CategoryFilterModal** — Already a separate component
3. **DeleteConfirmModal** — Delete confirmation dialog
4. **ProductDetailDrawer** — Product detail view (stock, financial, audit)
5. **StockAdjustModal** — Stock adjustment form

### ProductsPage Scope
- Product table (name, SKU, barcode, category, price, cost, status)
- Search, sort, category filter, pagination
- Add/Edit/Delete product modals
- Product detail drawer (without stock-focused features)
- Permission: `canManageInventory` for CRUD

### StockPage Scope
- Stock-level table (product name, category, current stock, stock status badge)
- Low-stock filter toggle
- Stock adjustment modal (quantity change + notes)
- Stock history/movements table (optional: API already supports `inventory_movements`)
- Search, sort, pagination
- Permission: `canAdjustStock` for adjustments

### API Endpoints (already exist)
- `GET /api/products` — Used by both pages
- `POST /api/products` — ProductsPage
- `PUT /api/products/:id` — ProductsPage
- `DELETE /api/products/:id` — ProductsPage
- `POST /api/inventory/adjust` — StockPage
- `GET /api/stock-thresholds` — StockPage (warning/critical thresholds)

### Permission Changes
- ProductsPage: `canManageInventory` (superadmin, admin, manager, staff) for CRUD; `canEdit` for edit/delete
- StockPage: `canAdjustStock` (superadmin, admin, manager, staff) for adjustments; read-only for all inventory roles

## Implementation Steps

### Step 1: Create shared components
- Extract `ProductFormModal.svelte` from InventoryPage form HTML
- Extract `StockAdjustModal.svelte` from InventoryPage stock adjustment HTML
- Ensure both accept props for form data, mode (add/edit), and emit events

### Step 2: Create ProductsPage
- Copy relevant sections from InventoryPage (table, add/edit/delete modals, detail drawer bottom)
- Remove stock-specific features (stock column, stock adjustment, low-stock toggle, stock field in form)
- Use extracted `ProductFormModal` component
- Route: `/inventory/products`

### Step 3: Create StockPage
- New page focused on stock levels and adjustments
- Table: product name, category, current stock, status badge (using `criticalThreshold`/`warningThreshold`)
- Low-stock toggle filter
- Stock adjustment modal (using extracted `StockAdjustModal`)
- Search, sort, pagination
- Route: `/inventory/stock`

### Step 4: Update routing (`App.svelte`)
- Add redirect: `/inventory` → `/inventory/products`
- Add route: `/inventory/products` → ProductsPage
- Add route: `/inventory/stock` → StockPage

### Step 5: Update Sidebar (`Sidebar.svelte`)
- Replace single Inventory item with expandable group:
  - "Products" → `/inventory/products`
  - "Stock" → `/inventory/stock`
- Handle collapsed state (show sub-items on expand)

### Step 6: Create E2E tests
- Create `tests/e2e/products.spec.ts`:
  - Navigate to `/inventory/products`
  - Verify product table loads with data
  - Test search, category filter, pagination
  - Test add product flow (fill form, submit, verify in table)
  - Test edit product flow
  - Test delete product flow
  - Test product detail drawer
  - Verify stock column is NOT present
- Create `tests/e2e/stock.spec.ts`:
  - Navigate to `/inventory/stock`
  - Verify stock table loads with non-zero stock values
  - Test low-stock toggle filter
  - Test stock adjustment flow (open modal, enter quantity+notes, submit)
  - Verify stock value updates after adjustment
  - Test search and pagination
- Run E2E tests iteratively until all pass

### Step 7: Create unit tests
- Create `ProductsPage.svelte.test.ts`:
  - Source-structure guard tests (form fields, table columns, permissions)
  - Verify stock-related features are absent
  - Test classifyStock logic
- Create `StockPage.svelte.test.ts`:
  - Source-structure guard tests (stock table, adjustment modal, low-stock toggle)
  - Verify product CRUD features are absent
  - Test threshold badge logic
- Run unit tests iteratively until all pass

### Step 8: Update existing tests
- Update `Sidebar.svelte.test.ts` for new nav structure (Products + Stock sub-items)
- Update `Home.svelte.test.ts` for updated quick link references
- Remove old `InventoryPage.svelte.test.ts`

### Step 9: Clean up
- Remove old `InventoryPage.svelte`
- Update any references in other files (Home page, Topbar, etc.)
- Run full test suite to confirm no regressions
