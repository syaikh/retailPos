# Fix Plan: Data Isolation by Store (Multi-Tenant)

## Problem Statement

Current system has **no data isolation between stores**:

1. **Priority 1 — Sales WebSocket broadcast leak**: `SalesService.CreateSale` broadcasts `sale.created` and `stock.updated` with empty `store_id` (""), which delivers events to **all** connected clients regardless of store. Cashiers in different cities see each other's transactions.

2. **Priority 2 — Products visible across all stores**: `ProductRepo` queries do NOT filter by `store_id`. Any cashier can see/inventory of all stores. Also missing `store_id` column on `products` table.

Both issues violate multi-tenant security. Fix must ensure each user only sees data from their own store, while admin (store_id=NULL) can see all.

- `Delete(id int, storeID *int) error` — optional: restrict deletion to own store

**Query building**: If `storeID != nil`, append `AND store_id = $n` to WHERE clause and add arg.

Example `GetAll` modification:
```go
func (r *ProductRepo) GetAll(limit, offset int, search string, groupID *int, sortBy, sortDir string, maxStock *int, storeID *int) ([]model.Product, int, error) {
    query := `SELECT ... FROM products WHERE deleted_at IS NULL`
    countQuery := `SELECT COUNT(*) FROM products WHERE deleted_at IS NULL`
    args := []any{}
    placeholderIdx := 1

    if storeID != nil {
        placeholder := strconv.Itoa(placeholderIdx)
        query += " AND store_id = $" + placeholder
        countQuery += " AND store_id = $" + placeholder
        args = append(args, *storeID)
        placeholderIdx++
    }
    // ... rest of filters (search, group, maxStock)
}
```

### Service Changes

**File: `internal/service/sales_service.go`**

Update `CreateSale`:

```go
func (s *SalesService) CreateSale(ctx context.Context, sale *model.Sale) error {
    tx, err := s.db.BeginTx(ctx, nil)
    // ...

    // 1. Get cashier's store_id
    cashier, err := s.userRepo.GetByID(sale.CashierID)
    if err != nil {
        return errors.New("failed to get cashier")
    }
    if cashier.StoreID == nil {
        return errors.New("cashier must be assigned to a store")
    }
    storeID := fmt.Sprintf("%d", *cashier.StoreID)

    // 2. Insert Sale with store_id
    querySale := `INSERT INTO sales (total_amount, payment_method, cashier_id, store_id) VALUES ($1, $2, $3, $4) RETURNING id, created_at`
    err = tx.QueryRowContext(ctx, querySale, sale.TotalAmount, sale.PaymentMethod, sale.CashierID, cashier.StoreID).Scan(&sale.ID, &sale.CreatedAt)
    // ...

    // 3. Broadcast only to this store (already storeID string)
    _ = s.hub.Broadcast(storeID, "sale.created", sale)
    for _, item := range sale.Items {
        _ = s.hub.Broadcast(storeID, "stock.updated", map[string]any{
            "product_id": item.ProductID,
        })
    }
    return nil
}
```

`GetProducts`:
```go
func (h *Handler) GetProducts(c *gin.Context) {
    // ... existing params
    storeIDInterface, exists := c.Get("store_id")
    var storeID *int
    if exists && storeIDInterface != nil {
        // Admin has nil store_id; cashier has int
        if sid, ok := storeIDInterface.(int); ok && sid != 0 {
            storeID = &sid
        }
    }

    products, total, err := h.productRepo.GetAll(limit, offset, search, groupID, sortBy, sortDir, maxStock, storeID)
    // ...
}
```

`GetProductByBarcode` (inside GetProducts barcode branch):
```go
if barcode != "" {
    storeID := h.getStoreIDFromContext(c) // helper
    p, err := h.productRepo.GetByBarcode(barcode, storeID)
```

Add helper:
```go
func (h *Handler) getStoreIDFromContext(c *gin.Context) *int {
    val, exists := c.Get("store_id")
    if !exists || val == nil {
        return nil // admin — all stores
    }
    if sid, ok := val.(int); ok && sid != 0 {
        return &sid
    }
    return nil
}
```

Update other product handlers (`UpdateProduct`, `DeleteProduct`) to check that the product belongs to user's store (unless admin). Use `productRepo.Update(product, storeID)` where repo ensures store match or admin bypass.

### Open Questions / Decisions Needed

1. **Should admin sales broadcast to all stores?**  
   Option A: Yes — empty `store_id` broadcasts to all (current behavior after fix: admin's store_id is nil, we'd broadcast empty → all receive)  
   Option B: No — admin actions silent, only cashier-generated sales trigger WS  
   **Recommendation**: Option A — admin is visible to all for transparency.

2. **How to handle products without store_id after migration?**  
   Option A: Set all existing products to store_id=1 (default)  
   Option B: Leave NULL → only admin can see them (since cashier queries filter store_id IS NULL? Our new query `store_id = $1` will exclude NULLs, so they'd be invisible to cashiers). This is safe.  
   **Recommendation**: Option B — leave NULL, admin-only. Safer.

3. **Do we need store_id on sale_items?**  
   Not strictly; can JOIN through sales. But for direct queries on sale_items, adding store_id denormalizes. For now, omit to keep simple.

4. **Should cashier be prevented from accessing other store's API directly?**  
   Yes — backend filters ensure this. Even if cashier manually calls `/api/products?id=999` for product belonging to Store B, repo will filter and return 404.
