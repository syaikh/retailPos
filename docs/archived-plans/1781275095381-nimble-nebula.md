# Plan: Merge StockPage into ProductsPage (Unified Product Management)

## Context

Currently `ProductsPage` and `StockPage` are separate pages with overlapping data (both show product name, SKU, category, stock). Best practice from POS systems (WCPOS, GSK POS, Howmuch POS) shows these should be **one unified page** where products and stock are managed together.

## Goal

Merge stock management features into `ProductsPage` as an integrated view, delete `StockPage`, and update routing/sidebar accordingly.

## Changes

### 1. `web/src/lib/pages/ProductsPage.svelte` — Add stock columns + adjust inline

**Table columns change** from:
`PRODUCT NAME | CATEGORY | PRICE | ACTIONS`

to:
`PRODUCT NAME | CATEGORY | PRICE | STOCK | STATUS | ACTIONS`

- Add **STOCK** column (sortable) — shows current stock quantity
- Add **STATUS** column — shows badge: Critical (red, ≤threshold), Low (amber, ≤warning), In Stock (green)
- Stock filter toggle button ("Low Stock") preserved from StockPage
- Actions dropdown already has `canAdjustStock` support — pass `true` instead of `false` for roles that can adjust

**Merge StockPage features into ProductsPage:**
- Import `StockAdjustModal` from `$lib/components/inventory/StockAdjustModal.svelte`
- Add `stockAdjustProduct`, `showAdjustStockModal`, `adjustingStock`, `stockAdjustForm` state
- Add `fetchThresholds()`, `openAdjustStock()`, `handleAdjustStock()` (lifted from StockPage)
- Add `warningThreshold`, `criticalThreshold` state + API fetch
- Import `ClipboardList` icon (for adjust action indicator)
- Import `AlertTriangle` icon for low-stock warning

**Permission for adjust:** `['superadmin', 'admin', 'manager', 'staff']` (same as StockPage's `allowedStockRoles`)

### 2. `web/src/lib/App.svelte` — Update routing

### 4. `web/src/lib/components/Sidebar.svelte` — Simplify nav

- Remove `showStockItem` derived value
- Remove the separate Stock item block from nav template
- Remove `ClipboardList` import (no longer needed in sidebar)
- Staff role: `staffMasterDataSubItems` was `[{label: 'Stock', ...}]` — change to `[]` (empty, staff sees nothing in master data since stock is now in products page and staff can't see products page... wait)

**Wait — reconsider staff role:** Currently staff sees Stock page but NOT Products page. If we merge, staff would lose stock access. Solution: keep a minimal "Stock" view for staff-only role.

**Better approach:** Don't delete StockPage entirely. Instead, make StockPage a **minimal read-only stock view** for staff role only, and merge full stock management into ProductsPage for admin/manager/superadmin.

Actually, the cleanest approach per best practice:

- **ProductsPage** = full product + stock management (for admin, manager, superadmin)
- **StockPage** = simplified stock-only view (for staff — no price, no edit, just view + adjust)

But this brings back the overlap problem. Let me reconsider.

**Final approach — keep it simple:**
- Merge everything into ProductsPage
- Staff role gets a **simplified ProductsPage** that shows: Product Name, Category, Stock, Status, Adjust button (no price, no edit/delete)
- This is controlled by the existing `canManageInventory` / `isSensitive()` checks already in ProductsPage

So the plan is:
- ProductsPage table shows stock columns for ALL roles
- Price column hidden for staff (already handled by `isSensitive()`)
- Edit/Delete hidden for staff (already handled by `canEdit()` / `canDelete`)
- Adjust button shown for staff (via `canAdjustStock` in actions dropdown)
- Delete StockPage entirely
- Staff sidebar: `staffMasterDataSubItems` was `[{Stock}]` → change to `[{Products}]` (they see the same page but with limited columns)
