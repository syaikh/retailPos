# WebSocket Real-time Stock Synchronization for POS

## Ringkasan
Implementasi WebSocket client di frontend untuk real-time stock synchronization pada halaman POS. Backend Go (internal/ws/hub.go) sudah broadcast event `stock.updated` dan `sale.created` setelah transaksi selesai. Frontend akan menerima event-event ini dan update UI secara otomatis tanpa reload, mencegah overselling di multi-terminal.

## Problem Statement
Saat ada beberapa kasir di store yang sama, cashier A menjual produk X, cashier B tetap melihat stock lama sehingga berisiko overselling. Solusi: real-time push dari server ke semua client POS.

## Goals
1. **Real-time stock accuracy** - Semua terminal POS ter-update secara instan ketika stock berubah
2. **User feedback** - Notifikasi visual saat transaksi tercatat
3. **Connection resilience** - Auto-reconnect dengan exponential backoff + jitter
4. **Non-blocking UX** - POS tetap operasional meski WebSocket terputus, dengan warning yang jelas
5. **Performance** - Debounced updates agar tidak membebani API saat burst events

## Technical Architecture

### 1. Infrastructure Layer
**File:** `web/src/lib/infrastructure/websocket.ts`

WebSocket client wrapper (pure TypeScript, no Svelte dependencies):

```typescript
type ConnectionState = 'disconnected' | 'connecting' | 'connected' | 'reconnecting';

class WebSocketClient {
  private url: string;
  private token: string;
  private storeId: string;
  private ws: WebSocket | null = null;
  private state: ConnectionState = 'disconnected';
  private handlers: Map<string, Set<(data: any) => void>> = new Map();
  private reconnectAttempts = 0;
  private reconnectTimer: number | null = null;
  private pingInterval: number | null = null;

  constructor(config: { url: string; token: string; storeId: string }) { ... }

  connect(): Promise<void> { ... } // upgrade HTTP→WS, auth via query param
  disconnect(): void { ... }
  send(message: any): void { ... }
  on(event: string, handler: (data: any) => void): void { ... }
  off(event: string, handler: (data: any) => void): void { ... }

  // Internal: exponential backoff dengan jitter
  private scheduleReconnect(): void {
    const baseDelay = Math.pow(2, Math.min(this.reconnectAttempts, 5)) * 1000; // 1s, 2s, 4s, 8s, 16s, 30s cap
    const jitter = Math.random() * 200; // ±200ms randomness
    const delay = Math.min(30000, baseDelay + jitter);
    this.reconnectTimer = window.setTimeout(() => this.connect(), delay);
  }

  // Internal: ping/pong heartbeat
  private startHeartbeat(): void {
    this.pingInterval = window.setInterval(() => {
      if (this.ws?.readyState === WebSocket.OPEN) {
        this.ws.send(JSON.stringify({ type: 'ping' }));
      }
    }, 54000); // 54s (below backend 60s idle timeout)
  }

  // Event dispatch
  private handleMessage(event: MessageEvent): void {
    const { type, payload } = JSON.parse(event.data);
    if (type === 'pong') return; // ignore pong
    this.emit(type, payload);
  }
}
```

**Auth:** Token dari `localStorage.getItem('token')` + `store_id` dari JWT claims (verify di auth endpoint atau decode JWT di client).  
**URL:** `ws://localhost:8080/api/ws?token=${token}&store_id=${storeId}`

### 2. Composable Layer
**File:** `web/src/lib/composables/useWebSocket.ts`

Svelte-friendly wrapper:

```typescript
import { writable, derived } from 'svelte/store';

export function useWebSocket(storeId: string) {
  const status = writable<ConnectionState>('disconnected');
  const lastError = writable<string | null>(null);
  let client: WebSocketClient | null = null;

  function connect() {
    const token = localStorage.getItem('token') || '';
    client = new WebSocketClient({ url: WS_URL, token, storeId });
    client.on('message', (msg) => {
      if (msg.type === 'stock.updated') handleStockUpdate(msg.payload);
      if (msg.type === 'sale.created') handleSaleCreated(msg.payload);
    });
    client.connect();
  }

  // Debounced refetch helper
  let refetchTimer: number | null = null;
  const debouncedRefetch = (callback: () => void, delay = 300) => {
    if (refetchTimer) clearTimeout(refetchTimer);
    refetchTimer = window.setTimeout(callback, delay) as unknown as number;
  };

  // Event handlers (will be set from POS page)
  let onStockUpdate: ((payload: { product_id: number }) => void) | null = null;
  let onSaleCreated: ((payload: any) => void) | null = null;

  function handleStockUpdate(payload: { product_id: number }) {
    if (onStockUpdate) {
      debouncedRefetch(() => onStockUpdate(payload), 300);
    }
  }

  function handleSaleCreated(payload: any) {
    if (onSaleCreated) {
      onSaleCreated(payload);
    }
  }

  onMount(() => connect());
  onDestroy(() => client?.disconnect());

  return {
    status,
    lastError,
    setStockUpdateHandler: (fn: (p: any) => void) => { onStockUpdate = fn; },
    setSaleCreatedHandler: (fn: (p: any) => void) => { onSaleCreated = fn; },
    disconnect: () => client?.disconnect(),
    send: (msg: any) => client?.send(msg)
  };
}
```

### 4. Stale Data Handling on Reconnect
Ketika koneksi WebSocket terputus lebih dari 30 detik, ada risiko data stock tidak sinkron. Saat reconnect berhasil:

```typescript
// Di useWebSocket.ts, after successful reconnect:
if (this.reconnectAttempts > 0) {
  // Trigger full data refresh
  this.emit('reconnected', { stale: true });
}
```

Di POS page:
```typescript
ws.on('reconnected', () => {
  // Force full refetch regardless of current query
  productSearch.search(searchQuery, posLimit, posOffset);
  ui.info('Koneksi pulih. Data stok telah diperbarui.', 3000);
});
```

## Error Handling & Edge Cases

### Authentication Failure (Close code 1008)
- Backend closes connection jika JWT invalid/expired
- Frontend: redirect ke `/login`, clear auth state, show toast "Sesi berakhir, silakan login kembali"

### Network Failure & Reconnect
- Exponential backoff: 1s → 2s → 4s → 8s → 16s → 30s (max) + jitter ±200ms
- After 5 failed attempts, show persistent toast: "Tidak dapat terhubung ke server. Periksa koneksi internet."
- Manual reconnect button? (tidak perlu, auto-reconnect cukup)

### Debounce Storm
- Multiple `stock.updated` events within 300ms → aggregated into single refetch
- Cancel pending refetch jika user mengganti search query sebelum timer fire

### POS Offline Mode
- Jika WebSocket disconnected, POS tetap fully functional:
  - Search products (API正常工作)
  - Add to cart
  - Checkout (backend validasi stok tetap jalan)
- UI: Show red indicator + pesan "Stok tidak real-time. Beberapa produk mungkin sudah terjual di terminal lain."
- Saat reconnect, auto-refresh untuk sync

## Implementation Steps

### Step 1: Infrastructure
1. Create `websocket.ts` with `WebSocketClient` class
2. Implement `connect()`, `disconnect()`, `on()`, `off()`, `send()`
3. Add exponential backoff + jitter in `scheduleReconnect()`
4. Add ping/pong heartbeat (send ping every 54s, ignore pong)
5. Parse incoming JSON, dispatch to registered event handlers
6. Handle close code 1008 → emit `auth_error` custom event

### Step 2: Composable
1. Create `useWebSocket.ts`
2. Initialize client in composable (call `connect()` on first use)
3. Maintain Svelte stores: `status`, `lastError`
4. Expose: `setStockUpdateHandler()`, `setSaleCreatedHandler()`, `disconnect()`
5. Add debounce utility for stock update refetch
6. Add `onDestroy` cleanup (clear timers, disconnect)

### Step 3: POS Page Integration
1. Import `useWebSocket`, instantiate in `onMount` (or top-level with `onMount` cleanup)
2. Extract `storeId` from auth store (`$auth.user.store_id`)
3. Register handlers: `handleStockUpdate()`, `handleSaleCreated()`
4. Implement `handleStockUpdate`:
   - If current `searchQuery.length >= 3`: call `productSearch.search(searchQuery, posLimit, posOffset)`
   - Else: clear products (search not active)
5. Implement `handleSaleCreated`: `ui.success('Transaksi #' + sale.transaction_code + ' berhasil')`
6. Add UI indicator di search bar (span with dynamic class)
7. Add tooltip based on `$wsStatus`

### Step 4: Stale Data Recovery
1. In `useWebSocket`, after successful reconnect (attempt reset to 0), emit custom `'reconnected'` event
2. In POS page, listen to `'reconnected'` and call full `productSearch.search()` (even if query empty, can skip or fetch all limited)
3. Show toast "Koneksi pulih. Data stok diperbarui."

## Performance Considerations

- **Debounce 300ms** prevents API storms from burst WebSocket events
- **Full refetch only on reconnect** (rare, acceptable)
- **No product cache complexity** in Phase 1 (simplicity > micro-optimization)
- **Minimal payload:** Backend already sends minimal `{product_id}` for stock updates
- **Connection pooling:** Single WS per browser tab (not per component)

## Risk & Mitigation

| Risk | Impact | Mitigation |
|------|--------|------------|
| Backend WS down | POS offline mode only, no real-time sync | Fallback to polling? No — POS still works, just no push. Show warning banner. |
| Memory leak (uncleaned handlers) | Crash after hours | Cleanup di `onDestroy` POS page: `client?.offAll()` |
| JWT expiration mid-session | Silent disconnect, stale data | Heartbeat detects stale? Better: include `exp` in JWT, calculate TTL, proactively reconnect before expiry |
| Burst events overload API | Rate limiting, 429 errors | Debounce 300ms already limits to ~3 calls/sec max even if 20 events incoming |
| Multi-store isolation bug | Store A receives Store B stock updates | Ensure `store_id` filter enforced di backend AND frontend sends correct `store_id` |
| Browser tab inactive → WS throttled | Missed updates | On tab focus (`visibilitychange`), trigger full refetch |

## Open Questions & Assumptions

1. **Store ID source:** Asumsi user payload from JWT sudahinclude `store_id`. Jika belum, perlu endpoint `/api/me` untuk fetch user profile setelah login.
2. **Backend payload consistency:** Asumsi `stock.updated` payload adalah `{ "product_id": number }`. Jika berbeda (e.g., `{ "id": ... }`), perlu mapping.
3. **Multiple product updates in single sale:** Backend broadcasts `stock.updated` per item. If sale 5 items → 5 events. Debounce akan aggregate.
4. **Pagination interaction:** Jika user sedang di page 2, refetch akan reset ke page 1 (karena offset tetap 0). Ini okay untuk konsistensi.
5. **Page visibility:** Jika user minimize tab, WS tetap connected (browser keepalive). Tapi browser mungkin throttle timers. On `visibilitychange` → refetch.
