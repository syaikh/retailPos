### Issue Analysis: Multiple Requests
The multiple requests during audit-log page loading are caused by **multiple Svelte reactive effects** triggering fetchLogs():

1. **onMount(fetchLogs)** - Initial load (line 80)
2. **searchQuery effect** - Runs when searchQuery changes (lines 59-62)
3. **selectedAction/offset/limit effect** - Runs when these values change (lines 64-69)

During component initialization, several of these values may be set/updated in sequence, causing multiple rapid requests.

## Proposed Solution

### 1. Optimize Frontend Request Triggering
Instead of having multiple independent effects that all trigger fetchLogs, consolidate into a single request trigger mechanism.

**Changes needed in `/web/src/lib/pages/admin/AuditLogs.svelte`:**
- Replace multiple `$effect` blocks with a single effect that depends on all relevant variables
- Implement proper request deduplication/cancelation for rapid successive requests
- Consider implementing request tracking to prevent duplicate requests

### 2. Backend Optimization (Optional)
While the endpoint exists, verify it's performing optimally:
- Check if pagination parameters (limit/offset) are properly utilized
- Ensure database queries use appropriate indexes
- Verify response payload size is reasonable

### 3. Alternative Approach: Request Deduplication
Implement a simple request tracking mechanism to prevent duplicate requests within a short timeframe.
