## Integration Plan

### Phase 1: Database Schema Extensions (Low Risk)
```sql
-- product_variants table
CREATE TABLE product_variants (
    id SERIAL PRIMARY KEY,
    product_id INTEGER REFERENCES products(id) ON DELETE CASCADE,
    sku VARCHAR(50) UNIQUE NOT NULL,
    barcode VARCHAR(50),
    color VARCHAR(50),
    size VARCHAR(50),
    weight_grams INTEGER,
    stock INTEGER DEFAULT 0,
    price_adjustment INTEGER DEFAULT 0
);

-- suppliers table
CREATE TABLE suppliers (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    code VARCHAR(20) UNIQUE,
    contact_person VARCHAR(100),
    phone VARCHAR(20),
    email VARCHAR(100),
    address TEXT
);

-- product_suppliers junction
CREATE TABLE product_suppliers (
    product_id INTEGER REFERENCES products(id) ON DELETE CASCADE,
    supplier_id INTEGER REFERENCES suppliers(id) ON DELETE CASCADE,
    supplier_sku VARCHAR(50),
    lead_time_days INTEGER,
    PRIMARY KEY (product_id, supplier_id)
);

-- product_images table
CREATE TABLE product_images (
    id SERIAL PRIMARY KEY,
    product_id INTEGER REFERENCES products(id) ON DELETE CASCADE,
    url VARCHAR(500) NOT NULL,
    alt_text VARCHAR(200),
    is_primary BOOLEAN DEFAULT false,
    sort_order INTEGER DEFAULT 0
);
```

### Phase 2: Backend Domain & Repository (Medium Risk)
- Add `ProductVariant`, `Supplier`, `ProductImage` domain types
- Add repository interfaces and implementations
- Extend Product struct with new relations

### Phase 3: API Handlers (Medium Risk)
- POST /products - accept extended fields
- GET /products/:id - include variants, supplier info
- PUT /products/:id - update extended fields
- New endpoints: /variants, /suppliers

### Phase 4: Frontend Form (High Impact)
- Restructure modal into tabbed sections:
  - Basic Info (name, sku, barcode, category, brand, description)
  - Pricing (cost, price, tax, discount, unit)
  - Inventory (stock, min, track, warehouse)
  - Variants (matrix for color/size, table view)
  - Supplier (dropdown + supplier SKU)
  - Media (image upload/preview)

## Impact Assessment

### Breaking Changes
- None expected - new fields are backward compatible

### Dependencies
- Frontend form refactor depends on API support
- Variant matrix UI requires significant new component

### Performance
- Variant queries may need indexing on product_id
- Image URLs stored as strings - consider CDN integration

### Migration Path
1. Deploy database migrations (additive only)
2. Deploy backend changes (new endpoints)
3. Deploy frontend in phases:
   - Phase A: Enhanced basic form (new fields)
   - Phase B: Variant support (new tab + table)
   - Phase C: Media support (upload + gallery)

---

## Recommended Implementation Order

1. **Immediate**: Extend frontend form with existing backend-supported fields
   - Add: brand dropdown, tax class dropdown, unit dropdown
   - Add: description textarea, weight field
   - Add: is_active_for_sale, is_active_for_purchase toggles

2. **Short-term**: Implement supplier system
   - Database tables for suppliers
   - API endpoints
   - Form integration

3. **Medium-term**: Product variants
   - variant matrix UI pattern
   - Each variant gets own SKU/barcode

4. **Long-term**: Media support
   - Image upload to storage (local/cloud)
   - Gallery component
