# Dummy Data Generator - Comprehensive Rewrite Plan

## Overview
Rewrite `/cmd/dummy/main.go` to inject fresh, realistic data with 4000-5000 products, 50-80 categories, and 4000-5000 sales transactions spanning 5-6 months. All data resembles real-world retail scenarios.

## Requirements
1. ✅ Truncate all data tables first (products, sales, sale_items, inventory_movements)
2. ✅ Products: 4000-5000 rows
3. ✅ Categories: 50-80 rows  
4. ✅ Sales transactions: 4000-5000 rows
5. ✅ Time span: 5-6 months for products and transactions
6. ✅ Administration data remains (users, roles, permissions, stores)
7. ✅ Real-world data quality
8. ✅ Transaction snapshot pricing: sale_items.unit_price preserves product price at transaction time

## Technical Implementation

### 1. Data Truncation (Start)
```sql
-- Disable triggers to avoid FK issues
TRUNCATE TABLE sale_items, inventory_movements, sales, products 
    RESTART IDENTITY CASCADE;
-- Categories remain (administration data)
```

### 2. Category Generation (50-80 rows)
- Start with existing database categories
- Generate additional realistic retail categories up to 70 total
- Categories include: Electronics subcategories (Phones, Laptops, Audio), 
  Fashion (Men/Women/Kids), Home (Furniture, Decor, Appliances), 
  Sports, Food & Beverage, Health & Beauty, Automotive, etc.

### 3. Product Generation (4000-5000 rows)
- Realistic product naming conventions
- SKU format: `{CATEGORY-CODE}-{BRAND}-{MODEL}-{VARIANT}`
- Price ranges by category:
  - Electronics: 500k - 15M IDR
  - Fashion: 50k - 2M IDR
  - Home: 100k - 5M IDR
  - Sports: 50k - 3M IDR
  - Food: 5k - 200k IDR
  - Books: 20k - 200k IDR
  - Beauty: 30k - 1M IDR
- Cost = 40-70% of price (realistic margins)
- Stock levels: 0-1000 units
- Random creation_date across 6-month window
- Each product linked to category_id

### 4. Sales Transaction Generation (4000-5000 rows)
- Invoice format: `INV-{YYYY}-{SEQ}`
- Random timestamps across 6-month window
- Cashier: random existing user_id
- Payment methods: Cash (40%), QRIS (35%), Debit (15%), Credit (10%)
- Status: 'completed' (all seeded transactions)
- 1-5 items per transaction
- **Critical**: unit_price captured from product.price at transaction creation time (snapshot)

### 5. Sale Items Generation
- Products randomly selected (weighted by category popularity)
- Quantities: 1-3 typical, up to 10 for small items
- subtotal = unit_price * quantity
- total_amount = sum(subtotals)

### 6. Inventory Movements (Optional)
- Can generate stock adjustment movements for realism
- Linked to product_id

## Data Quality Features

### Realism Elements
1. **Product naming**: Brand + Model + Variant (e.g., "Samsung Galaxy S23 Ultra 512GB")
2. **Category-specific pricing**: Electronics high-value, consumables low-value
3. **Temporal distribution**: More recent transactions slightly more frequent
4. **SKU consistency**: Format reflects category and sequence
5. **Stock correlation**: Older products may have lower stock
6. **Transaction patterns**: Weekday vs weekend variations

### Performance Considerations
- Batch inserts where possible
- Pre-fetch category IDs and user IDs
- Use prepared statements
- Progress logging every 500 rows
- Error handling with continue (don't fail entire run)

## Implementation Steps

### Phase 1: Foundation (Code Structure)
1. Define category list with 70 realistic retail categories
2. Define product templates per category (name patterns, price ranges)
3. Create helper functions for random data generation
4. Implement DSN configuration (maintain compatibility)

### Phase 2: Data Truncation
1. Execute TRUNCATE with CASCADE
2. Verify counts before proceeding

### Phase 3: Category Setup
1. Query existing categories
2. Generate additional ones up to 70
3. Build category_id lookup map

### Phase 4: Product Generation Loop
1. For i = 0 to target (4000-5000)
2. Select random category
3. Generate category-appropriate product data
4. Random date in 6-month window
5. Insert into products, collect ID
6. Log progress every 500

### Phase 5: Sales Generation Loop
1. For i = 0 to target (4000-5000)
2. Random transaction date (6-month window)
3. Random cashier
4. Insert sale record
5. Generate 1-5 sale items
   - Select random product
   - Capture current product.price as unit_price
   - Calculate subtotal
6. Update sale totals
7. Log progress every 500
