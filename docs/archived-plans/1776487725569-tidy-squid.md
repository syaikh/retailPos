# Fix Admin Role-Based Access Plan

## Problem Analysis

**Current Issue**: Even with admin role, the user can't access all pages. The permission check in `hooks.client.ts` isn't working for client-side navigation.

## Root Cause

`hooks.client.ts` only runs during **server-side rendering (SSR)**, not during **client-side navigation**! 

The flow:
1. Initial page load → SSR runs → hooks.client checks auth ✓
2. User logs in, then navigates client-side (e.g., click to /inventory) → hooks.client does NOT run ✗

So `hooks.client.ts` only protects the initial server render. After login, subsequent navigations bypass the hook entirely.

## Solution

Add client-side route protection in `(app)/+layout.svelte`. This layout wraps all protected routes and runs on every page navigation.

### Implementation

**File**: `src/routes/(app)/+layout.svelte`

```svelte
<script>
  import { onMount } from 'svelte';
  import { goto, beforeNavigate, afterNavigate } from '$app/navigation';
  import { page } from '$app/stores';
  import { auth } from '$lib/stores/auth';
  import { checkAuth } from '$lib/api/auth';
  
  let { children } = $props();
  let initialized = false;

  // Also do initial check
  onMount(async () => {
    await checkAuth();
    initialized = true;
  });

  // Before any navigation, check permissions
  beforeNavigate(async (nav) => {
    const state = $auth;
    
    // If not authenticated, redirect to login
    if (!state.user) {
      nav.cancel();
      goto('/login');
      return;
    }
    
    const path = nav.to.url.pathname;
    
    // Admin has full access
    if (state.user.role === 'admin') {
      return;
    }
    
    // Cashier restricted to /pos only
    if (state.user.role === 'cashier' && !path.startsWith('/pos')) {
      nav.cancel();
      goto('/pos');
    }
  });
</script>

{#if initialized}
  {@render children()}
{/if}
```

## Files to Modify

| File | Action |
|------|--------|
| `src/routes/(app)/+layout.svelte` | Add client-side route guard |

## Notes

- The existing hook at `hooks.client.ts` still provides server-side protection
- This adds client-side protection for SPA navigation
- Admin role check: `state.user.role === 'admin'` allows all routes
- Cashier role check: restricted to `/pos` only
