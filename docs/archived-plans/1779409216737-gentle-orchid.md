# Plan: Product Schema Cleanup + Config-Based Stock Thresholds

## Latar Belakang

Analisis struktur tabel `products` dan seluruh stack kode (DB → Go → Frontend) menemukan:
1. **5 kolom "dead columns"** — ada di schema dan domain Go tapi tidak pernah disimpan saat create/update, tidak pernah dibaca dari DB
2. **`stock_min` hardcoded** di `GetDashboardStats` (`= 5`) dan placeholder form frontend — tidak menggunakan nilai sebenarnya dari produk per baris  
3. **5 Phase 1 fields tidak di-persist** — ada di form state, tapi tidak sampai ke SQL INSERT/UPDATE
4. **`GetProductByID` / `GetAllProducts`** SELECT tidak memilih semua field produk yang ada di schema
5. **`dimensions_cm` & `default_discount_percent`** tidak ditangani di semua layer, dan `dimensions_cm` tidak ada di semua layer

---

## Penjelasan untuk Pembaca Pemula

Bagian ini menjelaskan setiap masalah dalam bahasa sederhana, tanpa jargon teknis yang berat.

### Masalah 1 — "Kolom mati" (Dead Columns)

Ada 5 kolom di tabel database yang seolah-olah "tidur". Mereka ada di skema dan definisi model Go, tapi tidak pernah disimpan saat membuat/mengedit produk, dan tidak pernah dibaca saat mengambil data produk dari database. Artinya: jika Anda mengisi kolom ini di form, nilai Anda akan hilang begitu submit, dan tidak akan muncul lagi saat produk ditampilkan. Kolom-kolom ini tidak berfungsi sama sekali.

Kolom tersebut: `is_track_expiry`, `is_track_batch`, `is_active_for_sale`, `is_active_for_purchase`, `dimensions_cm`.

### Masalah 2 — `stock_min` di-harcode menjadi 5

Saat dashboard menampilkan jumlah produk yang stoknya rendah, kode tersebut menggunakan angka **5** yang diketik langsung di kode (hardcoded), bukan mengambil nilai `stock_min` dari masing-masing produk. Artinya: jika sebuah produk punya `stock_min = 20`, tapi stoknya = 15, dashboard tetap menyebutnya **stok tidak rendah** karena threshold-nya hanya 5. Hasilnya akhirnya tidak akurat.

### Masalah 3 — 5 field lain tidak sampai ke database

Ada 5 field lagi yang ada di form frontend dan di model Go, tapi tidak pernah sampai ke perintah SQL yang menyimpan data. Artinya: meskipun pengguna mengisi form dengan benar, nilai itu diabaikan dan tidak tersimpan di database.

Kolom tersebut: `dimensions_cm`, `is_track_expiry`, `is_track_batch`, `is_active_for_sale`, `is_active_for_purchase`.

### Masalah 4 — Query produk tidak mengambil semua kolom

Saat mengambil data produk dari database, query hanya mengambil sebagian kolom, bukan semua. Artinya: beberapa informasi produk tidak akan tersedia di frontend meskipun itu ada di database.

### Masalah 5 — `dimensions_cm` & `default_discount_percent` tidak lengkap di semua layer

Field ini hanya ada di beberapa bagian sistem, tidak ada di bagian yang lain. Seperti rantai yang memiliki 5 mata rantai tapi 1 mata rantai hilang, rantai tidak akan berputar.

## Keputusan Desain: Threshold Stok via Config File (Option A)

### Masalah dengan `stock_min` per-produk di database

Menyimpan batas stok rendah di setiap baris produk (`products.stock_min`) memiliki kekurangan:
- **Tidak fleksibel** — Jika suatu saat ingin mengubah threshold dari 10 menjadi 15 untuk semua produk, harus update ribuan baris
- **Berat untuk query** — Tidak ada index yang bisa mempercepat perbandingan `stock <= stock_min` karena perbandingan melibatkan kolom per baris
- **Tidak sesuai skala multi-toko** — Setiap toko mungkin punya threshold berbeda, tapi `stock_min` saat ini per-produk saja

### Solusi yang dipilih: Config file global (Option A)

**File:** `.env` di root proyek

```env
# Stock Thresholds (global, berlaku untuk semua produk)
# Warning:  stok di bawah angka ini masuk kategori "perlu perhatian"
STOCK_WARNING_THRESHOLD=10
# Critical: stok di bawah angka ini masuk kategori "stok rendah"
STOCK_CRITICAL_THRESHOLD=5
```

**Alasan config file:**
- **Mudah diubah** — Ubah angka di `.env`, restart server, selesai. Tidak perlu migrasi database.
- **Tidak memberatkan query** — Perbandingan `stock <= 10` vs `stock <= stock_min` sama, tapi tidak perlu JOIN/SUBQUERY.
- **Support multi-environment** — Dev bisa `STOCK_WARNING_THRESHOLD=5`, staging bisa `20`, prod bisa `50`.
- **Single source of truth** — Semua threshold dipakai dari 1 tempat, tidak ada perbedaan antara dashboard dan badge frontend.

### Dua level threshold (bukan satu)

| Level | Nama | Kondisi | Tindakan yang diambil |
|---|---|---|---|
| Normal | Stok Aman | `stock > STOCK_WARNING_THRESHOLD` | Tidak ada notifikasi |
| Warning | Perlu Perhatian | `STOCK_CRITICAL_THRESHOLD < stock <= STOCK_WARNING_THRESHOLD` | Badge kuning, daftar di halaman inventory |
| Critical | Stok Rendah | `stock <= STOCK_CRITICAL_THRESHOLD` | Badge merah, alert dashboard, WebSocket broadcast |

### Rekomendasi nilai default (disetujui pengguna)

| Konstanta | Nilai Disarankan | Alasan |
|---|---|---|
| `STOCK_WARNING_THRESHOLD` | `10` | Barang yang stoknya di bawah 10 butuh diperiksa — ini adalah level di mana planner stok mulai mempertimbangkan pemesanan ulang. |
| `STOCK_CRITICAL_THRESHOLD` | `5` | Barang yang stoknya di bawah 5 benar-benar kritis — sangat berisiko kehabisan dalam 1-2 hari. |

### 0.2 Tambah config struct dan reader

**File:** `internal/config/config.go` — saat ini hanya 3 field:

```go
type Config struct {
    Env        string
    CORSOrigin string
    JWTSecret  string
}
```

Tambahkan 2 field threshold:

```go
type Config struct {
    Env                    string
    CORSOrigin             string
    JWTSecret              string
    StockWarningThreshold  int
    StockCriticalThreshold int
}
```

Update `Load()` untuk membaca dari env dengan default aman:

```go
func Load() *Config {
    env := os.Getenv("ENV")
    if env == "" {
        env = "development"
    }

    corsOrigin := os.Getenv("CORS_ORIGIN")
    if corsOrigin == "" {
        corsOrigin = "http://localhost:5173"
    }

    jwtSecret := os.Getenv("JWT_SECRET")
    if jwtSecret == "" {
        jwtSecret = "your-secret-key-change-in-production"
    }

    warningThreshold := 10
    if w := os.Getenv("STOCK_WARNING_THRESHOLD"); w != "" {
        if v, err := strconv.Atoi(w); err == nil && v > 0 {
            warningThreshold = v
        }
    }

    criticalThreshold := 5
    if c := os.Getenv("STOCK_CRITICAL_THRESHOLD"); c != "" {
        if v, err := strconv.Atoi(c); err == nil && v > 0 {
            criticalThreshold = v
        }
    }

    return &Config{
        Env:                    env,
        CORSOrigin:             corsOrigin,
        JWTSecret:              jwtSecret,
        StockWarningThreshold:  warningThreshold,
        StockCriticalThreshold: criticalThreshold,
    }
}
```

Pastikan `import "strconv"` ditambahkan jika belum ada.

### 0.3 Expose thresholds via API

Jika di kemudian hari timbul kebutuhan untuk mengembalikan `stock_min` per-produk:
1. Tambah migrasi: `ALTER TABLE products ADD COLUMN stock_min INTEGER DEFAULT 0;`
2. Tambah kembali ke `Product` struct di `internal/domain/user.go`
3. Tambah ke SELECT/INSERT/UPDATE di repository
4. Tambah kembali ke frontend form dan types
