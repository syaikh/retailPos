# Category Filter UI/UX Optimization Plan

## Overview
Implement fixes for three critical UI/UX issues in the Category Filter Modal, and implement the recommended "Opsi B" button-based layout for cleaner search bar presentation.

## Issues to Address

### Issue 1: Bug Counter Tombol "Terapkan Filter"
- **Problem**: Tombol "Terapkan Filter (1)" menampilkan angka meskipun semua checkbox tidak dicentang
- **Root Cause**: State `selectedCategories` mungkin memiliki nilai 'All' pada inisialisasi yang membuat `length > 0` bernilai true

### Issue 2: Tata Letak Bar Pencarian Berantakan
- **Problem**: Chips kategori terlalu banyak sehingga memakan ruang dan memompa kompresi pada input "Search products..."
- **Goal**: Ubah dari inline kategori input menjadi tombol "Kategori" terpisah
- **User Preference**: Opsi B (button-based) dengan tampilan dark mode dan aksen ungu

### Issue 3: Timing Trigger Filtering
- **Problem**: Setiap checkbox diklik langsung memicu API call — tidak efisien untuk 50+ kategori
- **Goal**: Deklarasi state lokal sementara selama modal terbuka, hanya commit ke state global saat "Terapkan Filter" diklik

## Implementation Steps

### Step 1: Add `tempSelectedCategories` to `CategoryFilterModal.svelte`
- Add `let tempSelectedCategories = $state([])` at top of script
- Update all existing `selectedCategories` references inside the component to use `tempSelectedCategories`
- Add `$effect` that copies from `selectedCategories` when modal opens
- Update `applyFilters` to commit `tempSelectedCategories` → `selectedCategories` then call `onApply`

### Step 2: Fix Button Counter Logic
- Replace `selectedCategories.length > 0` with filtered count check
- Example: `const activeCount = tempSelectedCategories.filter(c => c !== 'All').length`
- Only display counter when `activeCount > 0`

### Step 3: Replace kategori display in InventoryPage filter bar
- Replace entire `<div class="relative flex-1">` block (category dropdown) with a single `<button>`
- Button text toggles between "Kategori" dan "{N} Kategori Dipilih"
- Use inline Tailwind classes for dark gradient + purple accent

### Step 4: Verify `$effect` guards
- Ensure existing `$effect` for category change is not triggered by temp changes
- Add debug logging if needed for tracking state origins

### Step 5: Manual Testing Checklist
- [ ] Tombol "Terapkan Filter" tidak menampilkan angka saat mulai dari nol kategori
- [ ] Angka muncul sesuai jumlah kategori yang dipilih  
- [ ] Pencarian produk dari main bar tidak memengaruhi kategori state
- [ ] Setelah pilih kategori beberapa kali → Klik "Terapkan Filter" → data terbaru muncul
- [ ] Tutup modal tanpa klik "Terapkan Filter" → tidak ada fetch baru
- [ ] Reset Semua ⇒ tombol kembali ke "Kategori"
- [ ] Selected kategori ditampilkan sebagai badges di bar filter (max 3 + more count)
- [ ] Klik badge X ⇒ category dihapus dan fetch dijalankan dengan segera
