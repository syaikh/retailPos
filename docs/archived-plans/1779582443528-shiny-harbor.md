# PRD Reports Page Implementation Plan

## Overview
Restructure Reports.svelte to implement the Smart Dropdown Filter Terpadu (2-column unified selector) per PRD requirements.

## Current State Analysis

### What Needs to Be Removed (Breaking Changes)
1. **Manual date range pickers** (lines 507-517) - Manual input fields with Apply button
2. **Manual tab switching** (lines 562-581) - Daily/Weekly/Monthly buttons

### What Needs to Be Changed
1. **State management**: Replace `startDate`/`endDate` + `activeTab` with `selectedPeriodType`
2. **Chart logic**: Auto-switch chart type based on period selection
3. **UI layout**: Replace date pickers + tabs with unified dropdown

## Implementation Steps

### Phase 1: State Restructure
Replace the existing state architecture:
```javascript
// OLD
let startDate = $state(getDateNDaysAgoInJakarta(7));
let endDate = $state(getTodayInJakarta());
let activeTab = $state('daily');
let userOverriddenTab = $state(false);

// NEW (per PRD section 5)
let selectedPeriodType = $state('7days');  // realtime, yesterday, 7days, 30days, weekly, monthly, yearly
let dropdownOpen = $state(false);
let timezoneString = $state('GMT+07');
```

### Phase 2: Derived States
Implement derived states per PRD section 5:
```javascript
let chartType = $derived(
  ['realtime', 'yesterday'].includes(selectedPeriodType) ? 'hourly' :
  ['7days', '30days'].includes(selectedPeriodType) ? 'daily' : 'high-unit'
);

let statCardLabels = $derived({
  card4: 
    chartType === 'hourly' ? 'Peak Revenue Hour' :
    selectedPeriodType === 'yearly' ? 'Avg. Revenue / Month' :
    selectedPeriodType === 'monthly' ? 'Avg. Revenue / Week' : 'Avg. Revenue / Day',
  card5: 
    selectedPeriodType === 'realtime' ? 'vs Same Hours Yesterday' :
    selectedPeriodType === 'yesterday' ? 'vs Same Day Last Week' : 'vs Previous Period'
});
```

### Phase 3: Date Range Calculation
Implement `setPeriod()` function that:
- Sets `dateRange` start/end values
- Calls `fetchSales()` with appropriate API parameters
- Closes dropdown for simple modes (realtime, yesterday, 7days, 30days)

### Phase 4: UI Replacement
Replace date picker section (lines 506-517) and tab navigation (lines 562-581) with:
- Unified trigger button showing current period with timezone
- 2-column dropdown:
  - Left: Period options (Real-time, Yesterday, 7 Days, 30 Days, Weekly, Monthly, Yearly)
  - Right: Adaptive selector (for weekly/monthly/yearly modes)

### Phase 5: Chart Auto-Switch
Update `chartConfig` derived to handle:
- **Hourly mode** (realtime/yesterday): 
  - Type: line chart with hourly X-axis (00:00 to current hour / 24 hours)
  - Labels: "00:00", "01:00", ..., "23:00"
- **Daily mode** (7days/30days): line chart with daily dates
- **High-unit mode** (weekly/monthly/yearly): bar chart

### Phase 6: Backend Integration
Ensure API calls use correct endpoints:
- `/api/dashboard/chart` for daily/weekly/monthly (based on period)
- `/api/dashboard/comparison` for KPI calculations

## Key Technical Details

### Period Date Ranges (from PRD)
| Period | Start | End |
|--------|-------|-----|
| realtime | Today 00:00 | Current hour |
| yesterday | Yesterday 00:00 | Yesterday 23:59 |
| 7days | 7 days ago | Yesterday (excludes today) |
| 30days | 30 days ago | Yesterday (excludes today) |
| weekly | Weekly selector | - |
| monthly | Monthly selector | - |
| yearly | Yearly selector | - |

1. Remove `autoTab` and `autoChartType` derived states
2. Use `chartType` derived from `selectedPeriodType`
