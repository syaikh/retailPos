# Plan: Fix Payment Method Discrepancy Between POS and Reports

## Problem Analysis

### Current State
- **POS Cart UI** (web/src/routes/(app)/pos/+page.svelte:399-404): Only 2 options:
  - `cash` (Tunai)
  - `card` (Kartu)

- **Reports Page**: Displays `payment_method` from DB directly – can be any string

- **Database** (migrations/0001_initial.sql:35): `payment_method TEXT NOT NULL` – no constraint

- **Backend** (internal/service/sales_service.go:34-35): No validation – any string is stored as-is

### Root Cause
`sales.payment_method` has no constraints. The seeder (`cmd/seeder/main.go:133`) defines:
```go
var paymentMethods = []string{"cash", "debit", "qris", "transfer"}
```
So seeded demo data includes `debit`, `qris`, `transfer` – which appear in reports but not in POS UI.

---

## Solution

### Summary
1. **Fix seeder source** to only generate `cash` or `card`
2. **Rebuild seeder binary**
3. **Add DB CHECK constraint** to enforce `('cash','card')` using TRUNCATE + ALTER
4. **Add backend validation** in CreateSale
5. **Fix report labels** to show `'Tunai'` and `'Kartu'`
6. **Re-run seeder** to get clean demo data

---

## Implementation Steps

### Phase 1: Fix Seeder Source
- Edit `cmd/seeder/main.go:133`:
  ```go
  var paymentMethods = []string{"cash", "card"}
  ```
- Rebuild: `go build -o seeder ./cmd/seeder`

### Phase 2: Database Migration
- Create `migrations/0006_cleanup_payment_methods.sql`:
  ```sql
  BEGIN;
  -- Truncate sales cleanly (no row-level WAL logs, RESTART IDENTITY)
  TRUNCATE TABLE sales RESTART IDENTITY CASCADE;
  -- Add CHECK constraint to only allow 'cash' or 'card'
  ALTER TABLE sales ADD CONSTRAINT valid_payment_method CHECK (payment_method IN ('cash', 'card'));
  COMMIT;
  ```
- Apply migration (e.g., `psql -f migrations/0006_cleanup_payment_methods.sql`)
  - If app auto-runs migrations on startup, just restart the app

### Phase 3: Regenerate Clean Data
- Ensure app is stopped (to avoid DB lock), then run: `./seeder`
- Seeder truncates all tables and inserts fresh data using only `cash`/`card`

### Phase 4: Backend Validation
- Edit `internal/service/sales_service.go:26` (inside `CreateSale`):
  ```go
  if sale.PaymentMethod != "cash" && sale.PaymentMethod != "card" {
      return errors.New("invalid payment method: must be 'cash' or 'card'")
  }
  ```

### Phase 5: Frontend Display Labels
- Edit `web/src/routes/(app)/reports/+page.svelte`:
  - Add helper near top of `<script>`:
    ```js
    function getPaymentMethodLabel(method) {
      if (method === 'cash') return 'Tunai';
      if (method === 'card') return 'Kartu';
      return method;
    }
    ```
  - Replace `tx.payment_method` with `getPaymentMethodLabel(tx.payment_method)` at:
    - Table row: ~line 440 (within `{#each transactions as tx}`)
    - Export PDF: ~line 441 (inside `tableData.map`)
    - Export Excel: ~line 471 (inside data object)
  - Also in detail modal at ~line 672 if present

### Phase 6: Verification
- Verify DB: `SELECT DISTINCT payment_method FROM sales;` → only `cash`, `card`
- POS checkout: both methods succeed
- Any other method: returns 400 error from backend
- Reports table shows "Tunai" / "Kartu"
- Export PDF/Excel show labels correctly

- Rebuilding seeder is required because `seeder` binary is compiled from old source
- TRUNCATE is used to avoid heavy WAL logging; it's safe for dummy data
- Constraint prevents future invalid inserts even if seeder or API is misconfigured
- No changes needed in POS UI – already only offers cash & card
